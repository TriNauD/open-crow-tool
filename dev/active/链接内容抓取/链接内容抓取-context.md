# 链接内容抓取 — Context

> **来源**：BRAINSTORM 需求池 **D-1**（[`待办-D-链接内容抓取.md`](../BRAINSTORM需求池/待办-D-链接内容抓取.md)）  
> **立项性质**：**前瞻立项文档**（文档先行）。待阶段 2 / 排期确认后再编码。安全评审优先于功能花样。

## 背景 / 痛点

- 用户粘贴文章/文档 URL 时，当前模型**只看见字符串**，无法读正文，解释易空泛或幻觉。
- 路线图标重要度高、可行性中低——主因是 **SSRF、超时、反爬、版权与成本**。

## 现状（调研）

| 项 | 结论 |
|----|------|
| Explain | 无 URL 检测、无抓取；链接当普通 text |
| 服务端 fetch | 仅 `lib/github-trending.ts` 等固定 URL，**非**用户输入 |
| SSRF 防护 | 不存在（因无用户 URL fetch） |
| Middleware | 仓库无通用 URL 代理中间件 |

## 约束

- **禁止**服务端随意请求内网/metadata IP（AWS/GCP/localhost/链路本地等）。
- 须：协议仅 http(s)、DNS 解析后校验公网、超时、最大响应字节、内容类型白名单（html/text 优先）。
- 失败降级：抓取失败仍用「仅 URL 字符串」解释，并短提示「没读到正文」。
- 遵守 robots/站点 ToS 的产品态度：MVP 可只做「尽力而为 + 用户自担」，法律文案阶段 0 确认。

## 关键决策（待用户确认）

| 选项 | 说明 | 推荐默认 |
|------|------|----------|
| **触发** | 检测到唯一 URL 自动抓 vs 用户点「读取链接」 | **点选确认**（更安全可控） |
| **架构** | `/api/fetch-url` 独立 vs explain 内联抓取 | **独立 API**，explain 只收 `pageText` |
| **抽取** | 简单可读性算法 / Mozilla Readability / 第三方 | **MVP：去标签截断纯文本**；质量不够再上 Readability |
| **缓存** | 按 URL hash 短 TTL | 可选，防刷 |

## 依赖与风险

- **依赖**：Node fetch、可能的额外依赖（Readability）；Vercel serverless 超时预算。
- **风险**：SSRF 漏网、被目标站封、大页 OOM、钓鱼页内容进模型。
- **与 C-2**：图片多模态独立；链接以文本抽取为主。
