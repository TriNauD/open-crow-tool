# 笔记分类 — 保姆级手动测试

> 合入 `fea/future-features` 后、正式合 `dev` 前使用。  
> 自动化：`npm run lint`、`npm run test`（含 `__tests__/note-tags.test.ts`）。

## 环境

| 项 | 说明 |
|----|------|
| 分支 / 部署 | 本地：`fea/future-features`（或含本功能的功能分支）→ `npm run dev`；或 future 相关 Preview（若有） |
| 本地 URL | 通常 `http://localhost:3000` |
| 账号 | 准备一个**已登录**账号；另开无痕窗口测**游客** |
| 前置 | `.env.local` 已配置；笔记本多用户开关开启（与现网一致）；浏览器可开 DevTools → Network / Console |

## 前置数据（建议）

1. 登录后打开首页，问 2～3 个词并**保存到笔记本**（可不选分类，默认未分类）。
2. 记下其中一条的原文关键词，方便后面搜索。

---

## A. 登录态：改分类 + chip 筛选

1. 打开 `/notebook`。  
   **预期**：列表出现刚存的笔记；顶部有 chip：**全部**、**未分类**（此时可能还没有具体类名 chip）。
2. 点开一条笔记展开 → 点「编辑分类」→ 输入 `RAG` →「保存分类」。  
   **预期**：卡片标题旁出现绿色 `RAG`；顶部 chip 多出 `RAG`；刷新页面后仍在。
3. 再展开同一条 → 清空分类输入框 →「保存分类」。  
   **预期**：显示「未分类」；若没有其他 `RAG` 笔记，chip 栏可能不再显示 `RAG`。
4. 给笔记 A 设为 `工具`，笔记 B 保持未分类。点 chip「工具」。  
   **预期**：只看见笔记 A。点「未分类」只看见 B（及无 tags 的旧笔记）。点「全部」两条都在。
5. 在筛选「工具」时，搜索框输入笔记 A 的关键词。  
   **预期**：仍能看到 A；若搜笔记 B 的词则列表为空（搜索 ∩ 分类）。

**失败看哪里**：Network 里 `PATCH /api/notes/<id>` 是否 200；body 是否 `{ "tags": ["…"] }`；Console 报错；Supabase RLS / 503「Notebook multi-user mode」。

---

## B. 游客态：localStorage 分类

1. 无痕 / 退出登录 → 首页保存 1 条笔记 → `/notebook`。  
   **预期**：游客列表可见；可编辑分类（不走云端 PATCH）。
2. 设分类为 `杂项` → **硬刷新** F5。  
   **预期**：分类还在。  
   **失败看哪里**：Application → Local Storage → `crow_guest_notes_v1` 是否含 `"tags":["杂项"]`。

---

## C. 游客迁移带 tags（可选）

1. 游客笔记带分类 → 登录 → 出现迁移弹窗 → 确认迁移。  
   **预期**：云端笔记本里该条仍带同一分类。  
   **失败看哪里**：`POST /api/notes/migrate-guest` 请求体 entries 是否含 `tags`；响应 `insertedCount`。

---

## D. 旧数据兼容

1. 找一条从未设过分类的旧笔记（或 DB 中 `tags = {}`）。  
   **预期**：显示「未分类」，页面不报错；可正常改分类。

---

## E. 回归（短）

1. 删除一条笔记 → 列表减少，刷新后不回来。  
2. 扩展来源笔记（有「插件」徽章）仍可展开/删/改分类。  
3. 首页保存新笔记 → 笔记本出现，默认未分类。
