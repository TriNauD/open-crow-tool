# 飞书等平台 — Context

> **来源**：BRAINSTORM 需求池 **D-2**（[`待办-D-飞书等平台.md`](../BRAINSTORM需求池/待办-D-飞书等平台.md)）  
> **立项性质**：**前瞻立项文档**（文档先行）。待阶段 2 / **商业优先级**确认后再编码。  
> 路线图可行性「低～中」：强依赖飞书开放平台能力与是否值得维护第二端。

## 背景 / 痛点

- 部分目标用户在 **飞书文档** 内阅读，无法使用 Chrome 划词扩展。
- 期望「在飞书里也能解释术语」，与 Crow Web/扩展体验对齐。

## 现状（调研）

| 项 | 结论 |
|----|------|
| 代码 | **无**飞书/Lark SDK、机器人、文档插件、OAuth 回调 |
| 可复用 | 已有 `POST /api/explain`（CORS/文本流）与笔记本 Bearer API——理论上可作后端 |
| 扩展 | Chrome MV3 content script **不能**直接跑在飞书桌面客户端 WebView（除非其内嵌 Chromium 且允许扩展，通常不可用） |

## 约束

- 须先搞清飞书侧载体：**文档小组件 / 机器人斜杠命令 / 独立网页 H5 / 浏览器打开飞书网页版 + 现有扩展**。
- 密钥走 `env-and-secrets`：`FEISHU_*` 前缀；不得进仓库。
- 无明确商业/使用场景时，**禁止**大铺多平台抽象。

## 关键决策（待用户确认）

| 选项 | 说明 | 推荐默认 |
|------|------|----------|
| **P0 调研结论** | 仅文档评估 1～2 周，不写生产代码 | **先做** |
| **A. 飞书网页版 + 现有扩展** | 若用户用浏览器开飞书文档，验证扩展是否可用 | **最低成本试点** |
| **B. 飞书机器人** | 用户贴词/链接触发解释 | 交互重，适合异步 |
| **C. 飞书文档插件/小组件** | 真·站内划词 | 工程与审核成本最高 |

**本期文档建议范围**：完成平台选型结论 + 若选 A 则只补测试报告；若选 B/C 再开 `fea/*` 实现子阶段。

## 依赖与风险

- **依赖**：飞书开放平台账号、应用审核、可能的企业租户权限。
- **风险**：API 变更、桌面端与网页端行为不一致、维护第二客户端分散火力。
- **与 C-3**：扩展内登录不解决飞书桌面；勿捆绑排期。
