# 飞书等平台 — Plan

> **分支建议**（若进入实现）：`fea/feishu-integration-tri`  
> **池条目**：D-2（单独立项）  
> **建议节奏**：先「调研里程碑」再「可选实现里程碑」

## 目标

1. 明确 Crow 在飞书场景的**值得做的载体**与不做清单。
2. 若商业确认：交付一个最小可用集成（优先复用 `/api/explain`）。
3. 鉴权：飞书用户 ↔ Crow 用户映射策略清晰（或明确「仅匿名解释、不存笔记」）。

## 非目标

- 同期做钉钉/企微/Notion 全平台。
- 在无选型结论前引入大型 SDK 与复杂事件订阅。

---

## [PM] 验收要点（草案）

### 调研里程碑（可单独验收）

- 输出一页结论：推荐 A/B/C + 工作量 + 风险 + Go/No-Go。
- 验证「浏览器打开飞书文档 + 现有 Chrome 扩展」是否覆盖 80% 诉求。

### 实现里程碑（仅 Go 后）

- 选定载体上：用户提交词条 → 返回大白话解释（流式或一次性）。
- 错误与未登录行为可预期；无密钥泄漏。

---

## [TL] 技术方案

### 阶段 R：调研（无业务代码或仅 spike 分支）

| 探查项 | 方法 |
|--------|------|
| 网页版划词 | 真机：feishu.cn 文档 + 已装扩展 |
| 开放能力 | 阅读飞书文档小组件 / 机器人 / 网页应用文档，记录权限与回调 |
| 后端复用 | 评估直接调 `POST /api/explain` vs 包一层 `POST /api/feishu/...` 验签 |

### 若选型 B（机器人）骨架

- 事件订阅 URL（Next route）验签 → 抽文本 → 调 explain（可非流式拼完再回）→ 卡片消息。
- Env：`FEISHU_APP_ID` / `FEISHU_APP_SECRET` / `FEISHU_VERIFICATION_TOKEN` 等。

### 若选型 C（文档插件）

- 独立前端包 + 飞书应用配置；复用站点 OAuth 或独立 token 兑换 Crow session——工作量单列。

### 涉及文件（实现期预估）

- 新：`app/api/feishu/**`（若需要）
- `docs/tech/` 集成说明、`docs/product/` 场景说明
- **不改**核心 explain 语义，仅适配器

### 风险与回滚

- 回滚：禁用路由 + 撤飞书应用事件订阅。
- 依赖单独 PR。
