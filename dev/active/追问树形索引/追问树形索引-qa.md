# 追问树形索引 — QA

> 自动化命令：`npm run test`（Vitest，含 `__tests__/card-tree.test.ts`）；扩展 E2E：先构建 `chrome-extension/dist` 再 `npm run test:e2e:ext`（见 `docs/tech/chrome-extension-e2e-and-regression.md`）。

## 用例表

| ID | 场景 | 步骤 | 预期 | 自动化 |
|----|------|------|------|--------|
| T1 | 浅层不出现 | 划词解释后追问 1~2 条（单层） | 无把手、无浮层，卡片外观与旧版一致 | 手测 |
| T2 | 阈值出现 | 继续追问至 3 张子卡 | 主卡左缘自动出现索引把手 | 手测；阈值边界 `card-tree.test.ts` |
| T3 | 嵌套阈值出现 | 任一子卡内追问（出现孙卡） | 把手出现 | 手测 |
| T4 | 收起 / 展开 | 点把手展开浮层 → 再点收起 | 浮层树展开/收成把手，反复切换正常 | 手测 |
| T5 | 点击定位+高亮 | 点某一节点 | 平滑滚到对应卡片，橙色高亮约 1.2s 后消退 | 手测 |
| T6 | 折叠自动展开 | 先折叠目标卡（或其祖先），再点对应节点 | 先展开折叠的卡片，再定位+高亮 | 手测 |
| T7 | 跳转后不被拉走 | 跳转到顶部某节点后等待 | 视图停留在目标处，不被「跟随滚到底」拉回底部；手动下滚后出子卡仍可恢复跟随 | 手测 |
| T8 | 主卡折叠态可用 | 折叠主卡 body（N 条追问徽章）后点树节点 | 主卡 body 自动展开并定位 | 手测 |
| T9 | 贴左缘 clamp | 把卡片拖到屏幕最左缘再展开索引 | 浮层不越出视口（clamp） | 手测 |
| T10 | 长问题截断 | 用长句追问后看节点 | 两行截断（CSS ellipsis），不撑破浮层 | 手测 |
| T11 | 保存回归 | 有索引状态下保存笔记 / 查重（都保留 / 覆盖） | 保存链路与无索引时完全一致 | 手测 + 既有单测 |
| T12 | 销毁清理 | 关闭主卡（Esc / 点外部） | 无残留 portal 节点与监听器；重新划词一切正常 | 手测 |

## 自动化对表

- Vitest：`__tests__/card-tree.test.ts` —— 树构建、注册/注销、阈值 `shouldShowIndex`、祖先链展开顺序。
- E2E（可选，视 fixture 能力）：`e2e/extension-crow-bridge.spec.ts` 追加「3 条追问 → 把手出现 → 点节点定位」一条。
