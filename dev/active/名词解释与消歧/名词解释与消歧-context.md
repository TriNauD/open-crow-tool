# 名词解释与消歧 — Context

> **来源**：BRAINSTORM 需求池 **C-1**（[`待办-C-名词解释与消歧.md`](../BRAINSTORM需求池/待办-C-名词解释与消歧.md)）  
> **立项性质**：**前瞻立项文档**（文档先行）。待阶段 2 / 排期确认后再编码。

## 背景 / 痛点

- 路线图标 C-1 **重要度高**：缩写（API、RAG、SaaS）与多领域同名术语易被「一本正经地讲错」。
- 现状完全依赖通用 `SYSTEM_PROMPT`，无「先消歧再解释」流程，也无结构化义项输出。

## 现状（调研）

| 项 | 结论 |
|----|------|
| Prompt | `lib/ai/prompts.ts`：`SYSTEM_PROMPT` + `buildExplainPrompt`；3～5 句大白话，无缩写/多义规则 |
| API | `POST /api/explain`：`{ text, context? }` 文本流 |
| Provider | `lib/ai/providers.ts` 多供应商 fallback；与本需求正交 |
| Web/扩展 | 共用同一 explain 管道 |

## 约束

- 保持「大白话、短输出」品牌调性；消歧**不能**变成学术长文或 Markdown 百科。
- 成本：避免默认二次模型调用（先分类再解释）除非产品接受延迟/费用。
- 与 B-2 `surroundingText`、D-1 链接正文可叠加；本需求以 **prompt/轻流程** 为主，不强制新表。

## 关键决策（待用户确认）

| 选项 | 说明 | 推荐默认 |
|------|------|----------|
| **A. 纯 Prompt 增强** | System/User 增加：缩写尽量给全称；多义时用一句点明「在…语境下」；surrounding 优先 | **推荐 MVP** |
| **B. 模糊时澄清 UI** | 模型先返回 2～3 义项 JSON，用户点选后再流式解释 | 体验好但改契约大 |
| **C. 术语表** | 维护高频缩写 glossary 注入 | 运维成本高，可二期 |

**多义输出形态**：仍一段话内消歧 vs 允许「也可能指…」一句 —— **推荐仍一段话，必要时末句点出其他义项**。

## 依赖与风险

- **依赖**：仅 AI 层 + 可选前端展示；无 DB migration。
- **风险**：Prompt 过严导致模型胡编全称；须强调「不确定勿编造全称」。
- **可行性**：路线图「中低」——因质量难自动化验收，须加强手测样例集。
