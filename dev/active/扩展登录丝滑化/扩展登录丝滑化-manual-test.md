# 扩展登录丝滑化 — 保姆级手动测试

> 前置：扩展 manifest **0.1.26+**（`cd chrome-extension && npm ci && npm run build` 后在 `chrome://extensions` 重新加载 `dist`）。构建 env 与 C-3 相同（`VITE_PUBLIC_SUPABASE_URL` / `VITE_PUBLIC_SUPABASE_ANON_KEY` / `VITE_PUBLIC_SITE_ORIGIN`，须与网站同一 Supabase 项目）。
> 关联：C-3 主路径手测见 [`../Chrome扩展内登录/Chrome扩展内登录-manual-test.md`](../Chrome扩展内登录/Chrome扩展内登录-manual-test.md)；本文件只覆盖**内嵌登录**三条新路径。

---

## A. 划词卡片内登录 → 自动续存（主路径）

1. 扩展 Options **退出登录**（确保未连接状态）。
2. 任意普通网页划词 → 点浮标 → 等流式解释完成。
   **预期**：卡片底部为「登录后可保存」按钮（不再直接跳设置页）。
3. 点「登录后可保存」。
   **预期**：**卡片内**展开邮箱/密码表单（带「取消」与「无法登录？打开扩展设置」小字），页面**不跳转**。
4. 先点「取消」→ 再点「登录后可保存」，输入正确邮箱密码 → 点「登录」。
   **预期**：表单收起；底部自动变为「存入笔记本」或**直接自动保存**（自动续存，无需再点）；保存成功显示「✓ 已存入笔记本」。
5. 打开网站笔记本确认该条已写入。
   **失败看哪里**：Options 页 Network 是否有 `POST …/auth/v1/token?grant_type=password`；`POST /api/notes` 的 Authorization 是否为新 token。

## B. 保存遇过期 → 内联重登 → 自动重试

1. 已登录状态划词并等解释完成。
2. 制造过期：Options「退出登录」前先在**另一个已划词的标签页**保持卡片打开；或用 DevTools 将 `chrome.storage.local` 的 `accessToken` 改为无效串（刷新卡片所在页后重新划词亦可）。
3. 点「存入笔记本」。
   **预期**：出现「⚠️ 登录或连接已过期，**重新登录** 后自动继续保存，或回网站点『连接插件』」。
4. 点「重新登录」→ 卡片内输入正确邮箱密码 → 登录。
   **预期**：自动重试保存并显示「✓ 已存入笔记本」，无需再手动点保存。
5. 重复确认场景：划一个**已存过**的词 → 保存出现「都保留 / 覆盖旧的」→ 改 token 为无效再保存触发过期 → 内联重登。
   **预期**：重登后自动按「覆盖旧的」完成，重复确认选择**不丢**。
   **失败看哪里**：Network 中 refresh 请求 400 后是否出现 password grant 请求；`POST /api/notes` 最终响应是否 2xx。

## C. Popup 内登录

1. 退出登录状态，点扩展图标打开 Popup。
   **预期**：Popup 内直接显示邮箱/密码表单（紧凑版），不再是「请打开设置登录账号」的纯提示。
2. 输入正确邮箱密码 → 登录。
   **预期**：表单消失，显示「✓ 已登录，在任意页面选词即可使用」。
3. 划词 → 解释 → 保存。
   **预期**：保存成功。
   **失败看哪里**：Popup DevTools（右键扩展图标 → 检查弹出内容）看登录请求；确认 `VITE_PUBLIC_*` 构建时已注入。
